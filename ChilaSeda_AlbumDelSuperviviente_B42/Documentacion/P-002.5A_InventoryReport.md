# P-002.5A — Inventario preliminar vanilla de medios impresos y coleccionables

Datos extraídos de las definiciones locales de Project Zomboid Build 42.21. Este inventario es preliminar; no valida cada objeto en runtime ni pretende ampliar el alcance V1 del álbum.

## Alcance y archivos

- `P-002.5A_ObjectDefinitions.csv`: 561 tipos `base:literature` de `media/scripts/generated/items/literature.txt`, con nombre EN/ES, FullType, `ReadType`, icono, `OnCreate`, capacidad de escritura, categoría propuesta, fuente de variantes, lectura, acciones, posibilidad de distinción, permanencia candidata y nivel A/B/C.
- `P-002.5A_PrintMediaVariants.csv`: 175 IDs derivados de claves `Print_Media_*_info` y `Print_Text_*_info`, con título EN/ES, recurso visual, texto, mapa y método de lectura.

En la tabla de variantes, **A = 155** tienen composición y texto; **B = 20** conservan metadatos, nombre o texto insuficiente para una apertura completa. Hay 133 variantes con ubicación en `PrintMediaDefinitions.MiscDetails`. Todas las variantes listadas tienen claves ES correspondientes en las tablas examinadas.

## Selección P-002.5

Se integra `FashionaBelle`, folleto publicitario vanilla, como segunda apertura. `Base.Brochure` (`base:literature`, `ReadType=photo`) declara `OnCreate=ItemCodeOnCreate.onCreateBrochure`; el contenido concreto se identifica por el `item:getModData().printMedia.id`, no únicamente por `FullType`. El medio usa el ID `fashionabelle` para la referencia geográfica y las claves:

- `Print_Media_FashionaBelle_title` / `Print_Media_FashionaBelle_info`
- `Print_Text_FashionaBelle_title` / `Print_Text_FashionaBelle_info`
- Composición: `media/textures/printMedia/FlyerPics/Fashionabelle.png` (lienzo declarado 1616×1131).
- Texto ES disponible en `media/lua/shared/Translate/ES/Print_Text.json`.
- Referencia de mapa vanilla: `fashionabelle`, rectángulo x=8050–8109, y=11480–11579, en `PrintMediaDefinitions.lua`.

Los catálogos citados por Chila no ofrecen, en las tablas vanilla de Build 42.21 revisadas, un juego comparable de claves `Print_Media` + `Print_Text` por título. `Base.Catalog` es un tipo genérico con `onCreateCatalogue`; las cadenas de título dinámicas no aparecen en `ItemName`, `Print_Media` o `Print_Text` bajo “Good Price”, “Feel Yourself” o “A.A. Ron”. Por eso el folleto tiene mejor cobertura completa para esta fase. Esta conclusión se limita a las definiciones y traducciones instaladas, no prueba que esos nombres no existan en datos Java internos.

## Comportamiento y mapa vanilla

`ISReadABook:displayPrintMedia` obtiene `printMedia.id/info/title/text` de `item:getModData().printMedia`, crea `PZAPI.UI.PrintMedia`, y traduce las claves con `getText`. La ventana muestra botones de mapa si el ID está en `PrintMediaDefinitions.MiscDetails`; cada botón descubre los rectángulos asociados con `WorldMapVisited:setKnownInSquares` y luego abre el mapa en el centro del área. `onCreate` asigna los datos a la instancia, así que las ediciones deben distinguirse por ModData/nombre y no solo por `FullType`. La opción `getOptionAutoRevealPrintMediaMapLocations()` también puede revelar áreas al completar/mostrar la lectura.

La apertura personalizada añade un icono de mapa que invoca la ventana nativa para `fashionabelle`; se aprovecha allí la acción original. No se agrega índice general de mapas ni persistencia adicional.

## Identificación y persistencia

El ID base no distingue ediciones en objetos generados. El candidato estable es la tupla de `FullType`, `modData.printMedia.id`, claves title/info/text, nombre visible y datos de escritura. Para tarjetas y fotografías hay que conservar los campos generados por `OnCreate`; para notas de jugador, tipo base más texto/páginas. Vanilla registra lecturas de medios por jugador; el mod archivero debe enlazarlo al superviviente correspondiente y no depender del objeto físico. La persistencia por superviviente, supervivencia a borrado y restauración entre partidas todavía no se valida en runtime.

## V1 y siguientes fases

Prioridad V1 se mantiene en periódicos, folletos y mapas oficiales. Revistas, libros, documentación personal/administrativa y objetos escritos quedan inventariados como candidatos; el nivel C propone enriquecimiento futuro sin activar contenido nuevo. No se implementan P-002.6/7, catálogo funcional, índices interactivos ni cambios a descubrimiento/persistencia en este hito.

## Instrucciones de prueba en Build 42

1. Arranca Jill con `ChilaSeda_AlbumDelSuperviviente_B42` activo y abre el álbum personal.
2. Avanza a la apertura de Kentucky Herald y verifica que siga igual.
3. Avanza a la apertura FashionaBelle: composición original a la izquierda; texto español a la derecha.
4. Amplía con rueda, arrastra la composición, y desplázate sobre el texto derecho; comprueba independencia.
5. Pulsa el icono de mapa y usa el botón vanilla de ubicación para descubrir/abrir el área FashionaBelle de Rosewood.
6. Cambia temporalmente el idioma del juego y comprueba que el texto siga las claves del idioma; reabre para que `getText` se resuelva bajo el idioma actual.
7. Revisa `console.txt`/Error Magnifier; no considerar validado hasta confirmar en Jill.
