ChilaSeda - Weight Monitor (B42) 1.9.7

The monitor scans automatically while the game is running, even when its panel
is closed. It scans every 120 ticks (every 30 ticks while the panel is open).
It refreshes the game's nearby container lists before scanning the player's
inventory, nested bags, and reachable containers. `SCAN_STATUS OK` is written
only after both inventory pages refresh and every returned container is read.
Missing pages, failed refreshes, or unreadable containers produce
`SCAN_STATUS BLOCKED reason=...`; that scan does not mark unseen items Visto.
The monitor panel stays optional; no item transfer or manual collection is needed.

Each game session writes a dated UTF-8 text file under:
  Zomboid/mods/PesosLogs/WeightMonitor_YYYY-MM-DD_HH-mm-ss_<id>.txt

The monitor uses ZombieBuddy 2.3.0 or newer as an optional Java bridge. Without it, monitoring and its panel are skipped cleanly while the weight fixes remain active.

Its glass targets are synchronized with VanillaWeightFix: `Base.BrokenGlass` is
0.05 kg and `Base.GlassShiv` is 0.10 kg.

The monitor logs every item type found in the player's inventory, nested bags,
and nearby/reachable containers, including types without a configured target.
`Base.CorpseAnimal` entries are separated by animal type; skeletal animals use a target equal to 16% of their species midpoint live weight. It scans every 120 ticks (every
30 ticks while the panel is open). Each changed entry includes visible name,
technical ID, unit weight, combined weight, target (or `sin_meta`), count, Tetris
and script stack limits, stack status, and source container type/name/coordinates
where available. Entries are grouped
separately by container, so identical items in two containers keep independent
weights and counts. It records Visto
when a previously accessible type is no longer accessible. The panel is optional
and can be opened with Ctrl+Shift+F7.

At session start, the monitor also audits every loaded script item definition in
batches through Inventory Tetris. `STACK_CATALOG_PART` records each technical ID,
effective Tetris cap, original script cap, and `OK`/`REVISAR` status; the final
`STACK_CATALOG_END` line summarizes the counts. Accessible item entries and the
panel include `tetrisStack`, `scriptStack`, and `stackStatus`. A missing Tetris
API or unreadable item is marked `REVISAR` instead of being treated as verified.

Version 1.7.0 also emits `WEIGHT_CATALOG_PART` for every loaded definition with
the technical ID, script weight, script actual weight, configured target, and coverage label:
`MAPPED`, `DYNAMIC`, or `UNMAPPED`. `WEIGHT_CATALOG_END` gives the totals. This
catalog is an audit input: `MAPPED` means a local target exists, not that its
real-world value has been independently confirmed; `UNMAPPED` means the item
still inherits its game/mod weight; dynamic entries require an instance reading.
Version 1.7.2 labels the 12 hidden The Only Cure limb-display markers `BASE_OK`
when their declared actual weight remains 0 kg; a changed value is reported as
`REVIEW_MISMATCH`. It also shares the 0.25 kg target for `ThisIsYourLife.PreservedJournal`.
Version 1.7.3 adds the 0.0035 kg target for `Base.22Bullets`.

Statuses:
  OK       The observed weight matches the target within 0.005 kg.
  REVISAR  The observed weight differs from the target, or no target is configured yet.
  Visto    Seen earlier in this session, but no longer in accessible locations.

For stack limits, OK means Inventory Tetris reports exactly 100. REVISAR means
the effective Tetris cap differs from 100 or could not be read.

The monitor only reads item weights and stack limits; the neighboring weight-fix scripts change item
weights. It is packaged in the same mod ID and loads after target mods when they are present.
