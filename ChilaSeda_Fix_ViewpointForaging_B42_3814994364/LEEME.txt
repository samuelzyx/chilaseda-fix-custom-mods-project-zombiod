# Viewpoint Foraging Fixes

This local package groups fixes for the Workshop mod **Viewpoint Foraging**. Its folder and display name describe the full package; its internal mod ID is retained so the existing Jill profile continues to load it.

- **Foraging markers:** read the terrain at both the pin and the player through Rolling Hills' public `getSelectedHeight(x, y)` API, apply their relative height difference, then project with Viewpoint Foraging's public `project(...)` API. No private `Camera3D` fields or `luajava.bindClass` reflection are used. Diagnostic samples record both heights and the applied delta in `Zomboid\ViewpointRebusquedaHills\<session>.log`.
- **Optional per-area calibration:** press **Ctrl+Shift+Delete** to open a live adjustment panel. Height and one shared zoom value for the pin, target circle, and inner sprite preview live and persist with each area anchor. A single zoom field sets all three to the same 0.25–4.00x value; the paired buttons change it by 0.05x, like the height buttons. Existing anchors with separate legacy zoom values load into the shared field using their mean value. Nearby saved anchors blend by inverse-distance weighting, with exact anchor positions retaining their saved values. The right-side list opens any of the five most recently saved anchors; `Usar valores aqui` copies the selected values to the player's current location for a new anchor. `Guardar aqui` saves the values for the current area and `Borrar ancla` removes its closest anchor. Values are stored in `Zomboid\Lua\ViewpointRebusquedaHills_manual_offsets.txt`.
- **Pin recovery and audit report:** `Recargar pin` recalculates nearby seen pins and counts those that are actually on-screen and visible; it does not rely on a return value from Viewpoint Foraging's `placePin`. Manual height/zoom edits, anchor selection/copy/save/delete, and applying values immediately re-project nearby seen pins and report their actual visibility. The local placement hook restores UI visibility for eligible pins. `Registrar fallo` only audits nearby forage icons and appends visibility, item, texture, screen position, and size data to `Zomboid\Lua\ViewpointRebusquedaHills_pin_reports.log` for Codex to inspect later.
- **Diagnostics:** samples in `Zomboid\ViewpointRebusquedaHills\<session>.log` record the automatic correction separately from the chosen manual anchor, its offset, and final lift.
- **Shared key:** when Advanced Throwables shares G as its throw key, plain G remains available to pick up a foraging pin; intentional throwing requires **Ctrl+Alt+G**.

Requires ZombieBuddy and Viewpoint Foraging. Rolling Hills is optional: when present, its public
`getSelectedHeight(x, y)` API adds the automatic terrain-height correction. Without it, the original
3D pin projection and manual per-area height/zoom calibration still work. Advanced Throwables is
also optional; the shared-key guard loads only when its controller is available.

Version 1.3.15 updates the local patch's declared range through B42.22.2 and permits those optional
dependencies to be absent. The installed Workshop API (Viewpoint Foraging 0.3.0) was checked against
the hooks used here. Workshop originals and world data are unchanged; runtime confirmation in Jill
is still pending.

## Fixes in 1.3.10

- Saves the calibration panel's screen position in the existing settings file, restores it on the next open, and clamps it to the current screen bounds. Moving or closing the panel updates the saved position.

## Fixes in 1.3.9

- Height buttons now move by 5.0 instead of 0.10. One shared visual step changes pin, circle, and inner icon together by 0.05x (five percentage points).
- Uses nearby saved calibrations as weighted inputs between anchors instead of holding only the nearest anchor's values constant across a 64-tile radius.
- Lists the five most recently saved anchors; clicking one loads that zone, and `Usar valores aqui` copies its calibration to the player's current position.
- Protects all calibration-panel button callbacks; failures are logged and shown in the panel instead of breaking the UI. `Recargar pin` and `Registrar fallo` also handle callback failures explicitly.
- Adds the vanilla B42 search icon to the panel title.

## Fixes in 1.3.8

- Numeric zoom fields now parse their decimal text without passing `string.gsub`'s replacement count as `tonumber`'s base. This prevented saving, applying, and adjusting settings with `base out of range` errors.
- The Ctrl+Shift+Delete fallback now also polls `OnTickEvenPaused`, so the calibration panel can open while the single-player game is paused.


Version 1.3.11: localiza en español los rótulos, controles, valores y ayudas literales de Opciones > Mods > Viewpoint Foraging. Conserva el texto original cuando no está disponible la traducción española.

## Ajuste de zoom y reparación real de pines (1.3.13)

- El panel ahora tiene un único campo de zoom que aplica el mismo valor al pin, círculo e icono interior. Los botones `- 5 pts` y `+ 5 pts` cambian ese valor común en 0.05x; las anclas con escalas antiguas distintas se muestran con la media de las tres.
- Los reportes de antes de 1.3.12 mostraron pines elegibles con `visible=false`; 1.3.12 añadió `setVisible(true)` después de su colocación 3D. En 1.3.12, el contador de `Recargar pin` todavía requería `placed == true`, aunque el wrapper `VPF.placePin` devuelve `nil`; 1.3.13 cuenta directamente `vpfOnScreen` y `getIsVisible` después de recolocar cada pin.
- `Registrar fallo` sigue siendo diagnóstico y no repara pines. Los reportes de las 18:02:21 y 18:02:44 quedaron guardados correctamente.

## Re-proyección al ajustar anclas manualmente (1.3.14)

- Aplicar, editar altura/zoom, seleccionar o copiar un ancla, guardar y borrar ahora re-proyectan los pines vistos cercanos con la vista previa actual y muestran cuántos quedaron realmente visibles.
- El borrado limpia la vista previa antigua antes de consultar las anclas restantes, evitando que el valor temporal mantenga una calibración que ya se eliminó.
- La rutina verifica `vpfOnScreen` y `getIsVisible()` después de llamar a `VPF.placePin`; no presenta el intento como reparación si el elemento sigue oculto.

## Pines ocultos y botones de diagnóstico (1.3.12)

- Los reportes del 08/11 mostraron pines `seen=true`, `target=true`, proyectados dentro de pantalla y con `fade=1`, pero `getIsVisible()==false`. Viewpoint Foraging omite el dibujo de elementos UI ocultos; el fix vuelve visibles los pines elegibles después de cada colocación 3D.
- En 1.3.12 `Recargar pin` aún dependía de un resultado `true` de `placePin`, aunque la función no devuelve valor. La corrección del contador y la reparación real de visibilidad están en 1.3.13.
- `Registrar fallo` escribe diagnóstico para auditoría; no intenta reparar los pines. Los reportes de las 18:02:21 y 18:02:44 quedaron guardados correctamente.
